## What it is

SENEX Pictor is an open-source nightscape stacker in Rust (MIT OR Apache-2.0, © 2026 Michael
Anderson): a night of RAW frames from a tripod becomes one photo, with the sky stacked and the
foreground as it was shot. One binary, `pictor` (Pictor.app on macOS), opens the six-step desktop
app (Import, Frames, Sky & ground, Scene, Compare, Look & export; egui on wgpu) or, given a
command, runs the stacker headless (`process`, `check`, `stack`, `render`, `correct`, `flat`
and the rest, listed in the [README](README.md)).

- `src/`: the engine crate `pictor-engine`. `app/`: the app crate `pictor`.
- `vendor/`: LightCraft Classic's RAW decoder and a patched `egui-wgpu`, vendored and
  hash-locked (`docs/source-lock.json`).
- `data/`: built-in colour matrices and lensfun's lens database, both generated by `tools/`.
- Sibling app: SENEX Corvus, the importer
  ([github.com/endthestart/senex-corvus](https://github.com/endthestart/senex-corvus)). The two
  share the design tokens in [docs/DESIGN-TOKENS.md](docs/DESIGN-TOKENS.md).

## Run, test, package, release

```sh
cargo run --release -p pictor                                  # the app
cargo run --release -p pictor -- process RAW_DIR NEW_OUTPUT_DIR  # the stacker, headless
```

Checks. Format only the two first-party packages: `cargo fmt --all` rewrites vendored code,
which then fails the hash check.

```sh
cargo fmt -p pictor-engine -p pictor -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
python3 tools/verify_sources.py
```

Full tests. The UI tests skip quietly when their folders are not set, so mount the Work drive
and set all five:

```sh
PICTOR_UI_FOLDER=/Volumes/Work/star-photos-data/app-test/yellowstone-ui \
PICTOR_UI_CORRECT=/Volumes/Work/star-photos-data/app-test/yellowstone-correct \
PICTOR_UI_STOPPED=/Volumes/Work/star-photos-data/app-test/yellowstone-stopped \
PICTOR_UI_RAW=/Volumes/Work/star-photos-data/yellowstone-2013-08-27/raw \
PICTOR_UI_STACKED=/Volumes/Work/star-photos-data/app-test/bwca-stack \
cargo test --locked --release --workspace --no-fail-fast
```

- **Package:** `tools/package-macos.sh` builds `dist/Pictor.app` (universal, ad hoc signed)
  and `dist/Pictor-macos.zip`, refreshing the Third-Party Notices with `cargo-about` 0.9.3 first.
  It needs both macOS Rust targets and Xcode's command-line tools.
- **Release (owner's yes):**
  1. Bump `version` in `Cargo.toml` and `app/Cargo.toml`, and update the README's 0.1.0 section.
  2. Package.
  3. Tag the release and publish it on GitHub with the zip.
- **Refresh the built-in data:**
  1. `python3 -I tools/colour_matrices.py COLORDATA_CPP LIBRAW_VERSION` (LibRaw's
     `src/tables/colordata.cpp`).
  2. `python3 -I tools/lensfun.py VERSION_1_DIR PUBLISHED` (lensfun's `version_1.tar.bz2`,
     unpacked).
  3. Run `cargo fmt -p pictor-engine` and `tools/notices.sh`.
- **Icon:** `.venv/bin/python tools/icon.py app/assets/icon`.

5. **DNG colour matrices:** the ColorMatrix inside a DNG file is ignored, so DNG-only cameras
   missing from LibRaw's table (some Leicas, phones) stop at Import.
6. **Engine work**, listed under "Next bounded work" in [docs/status.md](docs/status.md):
   - re-audit the decoder (vendored Classic is at dbe90dc, upstream has moved on; truncated

   - end-to-end calibration, cross-checked against Siril;
   - a colour and master-format ADR;
   - a stellar PSF study.
7. **Matte:** lamp-lit swaying foliage (Maplewood) still needs painted corrections.
8. **Parked:** the HDR bracket merger (`tools/proto/hdr.py`) needs a tripod bracket shot at a
   fixed ISO 64.

## Known risks

- No CI: nothing checks `main` except a local run.
- About 800 cameras are matched by model name and checked against rawspeed's camera list, but
  not against photos. Cameras newer than LibRaw 0.22.1's table stop at Import until the table is
  refreshed.
- Linux and Windows builds compile, but have never been run, and the tests have never run on
  Linux.
- The full tests need the Work drive mounted and a GPU.
- A whole-sequence run can peak at about 14 GB of memory. On smaller machines, pass
  `--memory GB`.
- SSH to github.com on port 22 often times out from this network. Retry, or use `gh` over HTTPS.
